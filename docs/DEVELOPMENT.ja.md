# WebCapture

権限のある公開Webサイトをローカルへ保存し、管理画面と別のローカルOriginで隔離再生するアプリの開発者向け資料（日本語）。公開用の説明は英語の `README.md` を参照。

## できること

- URL階層を辿り、HTML、CSS、画像、GIF、SVG、フォント、動画、音声、JavaScript、描画後DOM、スクリーンショット、HTTP応答を保存
- Chrome / Edgeの隔離プロファイルと検査プロキシで、遅延読み込み、開閉UI、タブなど非送信操作後の状態を保存
- 保存中にタブ・開閉・メニューなど送信を伴わない操作を実際に行い、操作後に読み込まれる画像・API応答・スクリプトも保存する。保存するHTMLは操作前の状態
- 別ドメインの埋め込み（iframe）の子プロセスへ接続し、中の文書と素材を保存。親に届く通知だけで本体が子側にある文書も子側から取り直す
- 閉じたShadow DOM・入れ子のShadow DOM・文書全体の構築済みスタイルを宣言的Shadow DOMとして保存
- 動画・音声は部分取得のまま残さず全体を取り直し、HLS/DASHは配信リストを解析して全分割ファイルを保存。1件の上限（既定2 GB、無制限も可）を超えたものは記録し、アーカイブ画面から後で保存できる
- ページが読み込み時に送るPOST（GraphQL・検索APIなど）の要求本文と応答を保存し、再生時は本文のハッシュで照合して同じ応答を返す
- HTTPヘッダー・BOM・meta・@charsetから文字コードを判定して記録し、Shift_JIS・EUC-JPのページやCSSも文字化けさせずに再生
- 1ページの保存が制限時間を超えても、その時点までの描画後DOM・素材・リンクを保存して次へ進む。各段階の所要時間をログと保存記録に残す
- メニューなどマウスを乗せたときだけ出る表示を実際のマウス移動で出し、読み込まれる素材を保存する
- PDF・ZIP・画像など、ページ以外のリンク先もファイルとして保存し、再生では案内ページから別タブで開ける
- 同じURLでもページごとに内容が違う応答は別版として保存し、再生時はそのページで保存した版を返す
- WebGLで描かれたCanvasも画像として保存する
- 開始サイトとリンク先のホスト名に共通する固有キーワードを登録し、別domainでも関連サイトとして扱える
- 外部リンクは独立した取得深度を指定可能（1は最初の外部ページまで、2はそのページ内リンクまで）
- 高精度プロファイルは保存しながら構造を把握し、ページ数・容量・同一サイト深度・素材数・リンク数・実行時間を制限しない
- 必要な場合はHTMLだけの軽量探索で全体または指定ページ数の構造を先に把握してから本保存を開始
- 読み込み完了時に素材本体を順次回収し、画像・CSS・フォント・動画・JavaScript moduleを保存
- アーカイブタブから保存済み・途中停止・上限停止アーカイブを選択、再生、削除
- 構造把握を最大16並列、本保存を最大4並列で実行し、隔離ブラウザを再利用して起動コストを削減
- 複数ジョブは全体の公平な並列枠を共有し、CPU・メモリ・ディスク・通信・GPUが高負荷のときは新しい取得開始数を自動調整
- 端末全体の負荷を10秒ごとに数値だけ記録し、画面と診断APIで直近7日分を確認可能
- 高精度・標準・高速プロファイルで描画待機、遅延読込走査、並列数を連動切替
- 全`srcset`画像候補、open Shadow DOM、Canvas静止画、フォーム表示状態（password/fileを除く）を保持
- `picture`内の複数行`source srcset`も再生URLへ書き換え、PC・モバイル双方の画像候補をローカル再生
- ページ全体を120秒で安全停止し、ログイン誘導先は1回だけ保存して循環転送や無限描画待ちで巡回を止めない
- manifest・カウンターの保存確定をバッチ化し、WARCをgzipレベル1の可逆圧縮で保存
- SHA-256 blob、manifest.json、WARC 1.1 gzipとして保存
- 通常保存のWARC・manifest・件数・未処理URLを準備記録に確定し、途中終了したバッチは再起動時に重複なく復旧
- 素材実体とスクリーンショットを原子的に反映し、既存素材のサイズ・SHA-256不一致は成功扱いせず記録
- 低負荷モード（ON/OFF）: ONでは端末の負荷が高いときに同時保存数を自動で減らし、他の作業を安定させる
- 保存中・一時停止中の保存も、保存済みの分をアーカイブ画面で表示
- 時間切れ・通信エラー・アクセス過多・サーバーエラーのページは自動で最大2回取り直し、結果を記録
- 保存中は並列数と同じ数のタブで、裏で動いているChromeの実際の画面と今の工程をリアルタイムに表示（見るだけ。表示を隠すと画面の送信も止まる）
- 保存済みページ一覧、戻る・進む・再読み込み、リンク移動をブラウザ内ブラウザで再生
- 全ページ表示検査で保存済みページだけを隔離Chromeへ順番に表示し、画像、フォント、スクロール、通信失敗、JavaScriptエラーを副記録へ保存
- 同検査で送信を伴わない表示中の操作部品を1個ずつ安全に試し、操作前後2時点の変化・一時的な画面遷移・操作エラーを分離して記録
- 表示素材の欠落、決済・認証などの外部サービス境界、計測用通信、再生隔離イベントを別々に判定
- Shopify Web Pixels等の計測処理とShop Payの外部決済境界は、保存原本を残したまま再生時だけ外部接続しない無害なローカル応答へ置換
- Typekitの動的部分字体は同じ書体の保存済み完全字体へ安全に代替し、宣言的Shadow DOMの二重作成は保存済みrootを再利用
- 再生時の反復欠落ログは短時間で一括確定し、検査終了時はChrome・DevToolsタブ・検査proxyを上限付きで終了

## 安全境界

- 管理 `127.0.0.1:43193`、再生 `127.0.0.1:43194` だけで待受
- localhost、LAN、link-local、予約IP、クラウドmetadata、認証情報入りURLを拒否
- DNS確認後は検査済みIPへ接続を固定し、リダイレクトと素材も再検査
- ボタンの押下やフォーム送信による購入、削除、ログイン、投稿は実行しない。ページ自身が読み込み時に送るPOSTは記録のため通過させ、PUT・PATCH・DELETEとPOSTによるページ移動は遮断する
- 再生時の通信は保存済み素材へ置換し、POSTは保存済み応答の照会（GET）へ置き換える。GETフォーム、SPAの履歴移動、保存済みWorkerをローカル再生し、スクリプトによる外部への移動は止めて保存ページへ案内する
- 再生ページは元サイトのパスで動作し、再読込は保存ページへ戻る。埋め込み元の親画面（`app.config.json`の`iframeParentOrigins`）からの埋め込みでも再生枠を表示する
- robots.txtは任意の巡回ルール。robots許可は保存・再公開の権利許諾ではない

## 完全再現できないもの

閉鎖後の検索、投稿、認証、決済、コメント、WebSocket、WebRTC、Push、DRM、サーバー状態、利用者・時刻依存APIは再現できない。保存済みGET応答とクライアント側JavaScriptで動く範囲を再生する。

## 起動

AppDetail内の `Appboot_WebCapture.vbs` はサーバーと専用アプリウィンドウを起動する。`Appboot-background_WebCapture.vbs` は画面を開かずサーバーだけを起動する。

## 検証

- `npm test`: URL/SSRF/深度/保存/WARC/API/実ブラウザキャプチャ
- `npm run check`: 全JavaScript構文とAppDetail契約
- `npm run audit:archive -- <archive-id>`: 保存素材のSHA-256、サイズ、HTML、スクリーンショット、WARC gzip、空応答を監査し、`runtime/audits/`へJSON結果を保存
- アーカイブ画面の「全ページ表示検査」: 保存済みページを実ブラウザで検査し、進捗と問題ページを表示する。安全な表示操作も個別に試すが、送信操作や複数操作の全順列は実行しない。結果は`replay-audit.json`、重大な表示失敗の画像は`replay-audit/`へ保存し、manifestとWARC原本は変更しない
- `npm run repair:srcset -- <archive-id>`: 未保存srcset・拡大画像候補を安全なGETで補完し、manifest・WARC・件数を同期。アプリ停止中だけ実行でき、途中停止した更新は次回起動時に復旧する。元のページ本文は変更しない
- `npm run appdetail:check`: AppDetail必須14ファイル、JSON、原本、起動Controller

詳細な目的、範囲、設計上の限界は `PLAN.md`、恒久テストは `Test/README.md` を参照。

通常保存の復旧は新しい保存バッチから適用される。以前の保存で既に欠落した内容、ディスク自体の故障、電源断まで保証するものではない。検証用プロセスは`WEBCAPTURE_LOG_ROOT`でログ保存先を分離できる。通常起動のログ保存先は`runtime/logs/`のまま。

負荷記録は`runtime/metrics/metrics-YYYY-MM-DD.jsonl`へ保存する。端末名、ネットワーク名、IP、MACアドレスは記録しない。OSが取得できない値は0ではなく未取得として扱う。検証用には`WEBCAPTURE_METRICS_ROOT`で保存先を分離できる。
